# AmneziaWG Easy — VPN-стенд

Веб-управляемый WireGuard/AmneziaWG-сервер в Docker: админка через браузер, готовые
конфиги и QR-коды для клиентов, встроенный экспорт метрик Prometheus.

---

## Что это

| | |
|---|---|
| Образ | `ghcr.io/wowly/amnezia-wg-easy:latest` |
| Ревизия образа | `df0825c91dd47427714b71a5786bd59e9b6cb351`, собрано 2026-08-29 |
| Метка версии образа | 2.0.0 |
| Основа | [wg-easy](https://github.com/wg-easy/wg-easy) Эмиля Нейсена |
| Дополнение | [amnezia-wg-easy](https://github.com/spcfox/amnezia-wg-easy) Виктора Юдова |
| Реализация | Node.js, точка входа `dumb-init -- node server.js`, рабочий каталог `/app` |
| Протокол | AmneziaWG 2.0 (WireGuard с обфускацией заголовков) |
| Лицензия | `NOASSERTION` — условия в репозитории проекта |

AmneziaWG добавляет к WireGuard обфускацию: перед началом сессии отправляется заданное
число junk-пакетов случайного размера, а заголовки handshake-пакетов заменяются на
магические значения. Это ломает сигнатуру обычного WireGuard, по которой его детектируют
DPI-системы.

### Возможности

- Управление клиентами из Web UI: создание, редактирование, удаление, вкл/выкл.
- Скачивание конфига клиента и QR-код.
- Статистика подключений, графики Tx/Rx на клиента.
- Срок действия клиента (по умолчанию выключен).
- Одноразовые ссылки на скачивание конфига с истечением через 5 минут.
- Экспорт метрик Prometheus на том же порту, что и Web UI.
- 18 языков интерфейса, включая русский.

```

├── docker-compose.yml   # единственный сервис amnezia-wg-easy
├── .env                 # рабочие настройки, включая пароль и параметры обфускации
```

Состояние хранится в именованном томе `etc_amnezia_wg`, который монтируется в

параметрами обфускации и списком клиентов. **Том не входит в каталог и не переживает
`docker compose down --volumes`.**

Для развёртывания с нуля: `cp .env.example .env`, затем заполнить `WG_HOST` и
`PASSWORD_HASH`. В шаблоне перечислены все ключи, включая закомментированные
дополнительные параметры, и напоминание про имена без префикса `WG_`.

### Правила firewall по умолчанию

`WG_POST_UP` по умолчанию добавляет правила, которые **разрешают клиентам ходить в интернет,
но запрещают доступ в локальную сеть сервера**: блокируются `10.8.0.0/24`,
`192.168.0.0/16`, `172.16.0.0/12`, а также TCP-порт 51821 на интерфейсе `wg0`. Это осознанное
решение проекта. Если клиентам нужен доступ к LAN — правила нужно переопределить через
`WG_POST_UP`.

## Параметры обфускации AmneziaWG

Ключевая часть маскировки. Значения подставляются в серверную конфигурацию и в конфиги
клиентов. **Все параметры заданы явно в `.env`**, чтобы не смешивать заданные значения со
случайными — такое смешение само может стать признаком для DPI.

| Параметр | Смысл | Значение в `.env` | Что было бы по умолчанию |
|----------|-------|-------------------|--------------------------|
| `JC` | число junk-пакетов перед началом сессии | `6` | случайное 3–10 |
| `JMIN` | минимальный размер junk-пакета, байт | `10` | `50` |
| `JMAX` | максимальный размер junk-пакета, байт | `30` | `1000` |
| `S1` | размер junk в init-пакете, байт | `70` | случайный 15–150 |
| `S2` | размер junk в response-пакете, байт | `110` | случайный 15–150 |
| `S3` | padding cookie-reply, байт | `134` | случайный 15–150 |
| `S4` | padding транспортных пакетов, байт | `110` | случайный 15–150 |
| `H1` | магический заголовок init-пакета | `1943259813` | случайный |
| `H2` | магический заголовок response-пакета | `1843346077` | случайный |
| `H3` | магический заголовок UnderLoad-пакета | `282040757` | случайный |
| `H4` | магический заголовок транспортного пакета | `2083881407` | случайный |
| `I1` | шаблон сигнатуры 1 | `<r 969>` | случайный `<r N>` |
| `I2` | шаблон сигнатуры 2 | `<r 213>` | случайный `<r N>` |
| `I3` | шаблон сигнатуры 3 | `<r 415>` | случайный `<r N>` |
| `I4` | шаблон сигнатуры 4 | `<r 481>` | случайный `<r N>` |
| `I5` | шаблон сигнатуры 5 | `<r 114>` | случайный `<r N>` |

`JC`, `JMIN`, `JMAX` — ваши значения. `S3`, `S4`, `H1`–`H4`, `I1`–`I5` сгенерированы теми же
формулами, что использует сам проект (`getRandomJunkSize`, `getRandomHeader`,
`getRandomSignature`), и проходят его собственные проверки: `15 ≤ S3,S4 < 150` и шаблон
`<r N>` при `32 ≤ N < 1000`.

Допустимые теги в шаблонах `I1`–`I5`: `<b 0x…>`, `<r N>`, `<rd N>`, `<rc N>`, `<t>`.

### Как это применяется

Логика в `src/lib/WireGuard.js`:

1. Если тома ещё нет, при первом старте `wg0.json` **создаётся** — в него записываются
   значения из переменных окружения, а при их отсутствии — случайные.
2. Если `wg0.json` уже существует, он просто читается, а переменные окружения **игнорируются**.

Отсюда два практических следствия:

- Задать параметры обфускации нужно **до первого запуска**. После создания `wg0.json`
  правка `.env` на них не подействует.
- Миграция с AmneziaWG 1.x на 2.0 требует одновременной замены всех клиентских
  конфигураций, потому что `S3` и `S4` действуют на весь интерфейс.

## Запуск

```bash
cd /opt/compose/amnezia

# проверить, что порты свободны
ss -tulpn | grep -E "51820|51821"

docker compose up -d
docker compose ps
docker compose logs -f amnezia-wg-easy
```

Compose собирает не образ, а тянет готовый (`image:` без `build:`), поэтому нужен только
интернет. Первый старт дольше обычного: генерируется `wg0.json`, скачивается и
собирается `amneziawg-go`.

Остановить и удалить контейнер, **сохранив том**:

```bash
docker compose down
```

Удалить вместе с клиентами и ключами:

```bash
docker compose down --volumes
```

### Требования к хосту

Compose запрашивает у Docker две capabilities и одно устройство:

- `cap_add: NET_ADMIN` — управление интерфейсом `wg0` и правилами iptables.
- `cap_add: SYS_MODULE` — загрузка модуля ядра WireGuard.
- `/dev/net/tun` — передаётся в контейнер напрямую.
- `sysctl net.ipv4.ip_forward=1` и `net.ipv4.conf.all.src_valid_mark=1` — проксирование и
  маркировка пакетов.

Устройство `/dev/net/tun` должно существовать на хосте. Если контейнер падает с ошибкой про
TUN, модуль не загружен:

```bash
ls -l /dev/net/tun || modprobe wireguard
```

### Проверка состояния

Healthcheck задан в самом образе, в compose не переопределён:

```
/usr/bin/timeout 5s /bin/sh -c "/usr/bin/wg show | /bin/grep -q interface"
```

Интервал 60 с, таймаут 5 с, 3 попытки. То есть контейнер считается здоровым, пока
интерфейс `wg0` виден в выводе `wg show`. Команда в compose не задана, поэтому
`docker compose ps` покажет колонку `STATUS` со значением `healthy`.

```bash
docker inspect -f '{{.State.Health.Status}} restarts={{.RestartCount}}' amnezia-wg-easy
docker inspect -f '{{json .State.Health.Log}}' amnezia-wg-easy | python3 -m json.tool
```

Сбросить счётчик рестартов контейнера без пересоздания:

```bash
docker restart amnezia-wg-easy
```

## Web UI

Адрес: `http://<адрес-хоста>:51821`.

Логин — без логина, только пароль, который задан в `PASSWORD_HASH`. Значение — bcrypt-хеш,
а не сам пароль, поэтому сменить его через `.env` можно только новым хешем:

```bash
docker run --rm httpd:2.4-alpine htpasswd -nbBC 10 "" 'НОВЫЙ_ПАРОЛЬ' | tr -d ':\n'
```

Полученную строку положить в `PASSWORD_HASH` в `.env`. Если переменная пустая или удалена,
вход в админку не запрашивает пароль вовсе.

> **DNS.** Внешние клиенты получают в конфигах `WG_HOST` и резолвят его через публичный DNS.
> Локально на этом хосте `tmp.staff-rf.ru` отдаёт `10.54.5.94` — собственный адрес хоста,
> тогда как публичный DNS отдаёт `195.239.223.83`. Это не мешает клиентам снаружи, но
> локальные проверки через `openssl` или `curl` будут идти на сам хост и ничего не найдут.

## Метрики Prometheus

Экспорт включён переменной `ENABLE_PROMETHEUS_METRICS=true`. Точки:

| Путь | Формат |
|------|--------|
| `http://<хост>:51821/metrics` | текст Prometheus |
| `http://<хост>:51821/metrics/json` | JSON |

Метрики — по каждому клиенту, с лейблами:

```
wireguard_sent_bytes{interface="wg0",enabled="…",address="…",name="…"}
wireguard_received_bytes{interface="wg0",enabled="…",address="…",name="…"}
wireguard_latest_handshake_seconds{interface="wg0",enabled="…",address="…",name="…"}
```

Плюс агрегаты: число пиров, число включённых, число подключённых.

Готовый дашборд WireGuard для Grafana — [dashboard 21733](https://grafana.com/grafana/dashboards/21733-wireguard/).

**Метрики содержат имена клиентов и их VPN-адреса** и сейчас не защищены паролем, а порт
51821 открыт в интернет. См. «Известные проблемы».

## Что уже исправлено

### Параметры обфускации не применялись — исправлено

Раньше в `.env` стояли имена `WG_JC`, `WG_JMIN`, `WG_JMAX`, `WG_S1`, `WG_S2`. Исходник
проекта читает **другие** имена — без префикса `WG_`:

```js
// src/config.js
module.exports.JC   = process.env.JC   || getRandomInt(3, 10);
module.exports.JMIN = process.env.JMIN || 50;
module.exports.JMAX = process.env.JMAX || 1000;
module.exports.S1   = process.env.S1   || getRandomJunkSize();
module.exports.S2   = process.env.S2   || getRandomJunkSize();
```

Значения с префиксом `WG_` не читались нигде, поэтому при первом запуске параметры стали бы
**случайными**, а не `6/10/30/70/110`.

Сделано: в `.env` имена переименованы в `JC`, `JMIN`, `JMAX`, `S1`, `S2`, дополнительно
заданы `S3`, `S4`, `H1`–`H4` и `I1`–`I5`, а в файл внесена предупреждающая пометка.
Значения рабочие — это подтверждено разбором `docker compose config`: переменные доходят
до сервиса именно под этими именами.

**Важно:** правка действует только пока не создан `wg0.json`, то есть до первого запуска.

### Не было `.gitignore` и открытых прав на `.env` — исправлено

Ранее `.env` и `docker-compose.yml` лежали неотслеживаемыми, `.gitignore` отсутствовал, а
`git add .` закоммитил бы `.env` вместе с bcrypt-хешем от пароля админки. Права на файл были
`644`, то есть его читал любой пользователь хоста.

Сделано: добавлен `.gitignore` с записью `.env` (проверено — файл перестал отображаться в
`git status` и определяется через `git check-ignore`), права на `.env` выставлены в `600`.

### Логи контейнера не ограничены — исправлено

В `docker-compose.yml` добавлено ограничение роста логов, иначе `json-file` пишет
безлимитно:

```yaml
logging:
  driver: json-file
  options:
    max-size: 10m
    max-file: "3"
```

То есть на сервис — до 30 МБ логов, дальше старые ротируются.

## Известные проблемы

### 1. Метрики открыты в интернет без пароля

`ENABLE_PROMETHEUS_METRICS=true`, но `PROMETHEUS_METRICS_PASSWORD` не задан. В коде
требование пароля включается только если переменная непустая:

```js
const requiresPrometheusPassword = !!PROMETHEUS_METRICS_PASSWORD;
```

Значит `/metrics` и `/metrics/json` отдаются без аутентификации на порту, который
compose публикует на `0.0.0.0`. Наружу уходят имена клиентов, их адреса и объём трафика.

Оставлено как есть сознательно. Варианты, если решите закрыть:

- задать `PROMETHEUS_METRICS_PASSWORD` тем же bcrypt-хешем — Prometheus будет запрашивать
  Basic Auth;
- ограничить порт публикацией на `127.0.0.1` в `docker-compose.yml` — снаружи метрики
  станут недоступны, Prometheus должен собирать их с того же хоста.

### 2. Порты заняты

51820/udp и 51821/tcp уже заняты другим контейнером на этом хосте. До освобождения портов
или смены значений `WG_PORT` и `PORT` запуск не удастся.

| Симптом | Причина и что делать |
|---------|---------------------|
| `bind: address already in use` | порт уже занят — освободить или сменить `WG_PORT`/`PORT` |
| `no such device: /dev/net/tun` | не загружен модуль: `modprobe wireguard` |
| Контейнер перезапускается, в логах `SYS_MODULE` | ядро собрано без WireGuard или запрещена загрузка модулей |
| `Client's IP address is already in use` | адрес клиента совпал с существующим — задать другой `WG_DEFAULT_ADDRESS` |
| Клиенты не подключаются снаружи | проверьте `WG_HOST` через публичный DNS и проброс UDP на файерволе хоста |
| Метрисы не отдаются | `ENABLE_PROMETHEUS_METRICS` должен быть строкой `true`; проверьте `curl .../metrics` |
| Параметры обфускации не те | `wg0.json` уже создан — задавать надо было до первого старта |
| В админку пускает без пароля | `PASSWORD_HASH` пуст — вход не защищён |

## Безопасность

- `.env` содержит bcrypt-хеш пароля админки. Не коммитить и не публиковать: файл уже в
  `.gitignore`, а права выставлены в `600`. При изменении держите `600`.
- Порт 51821 открыт в интернет и отдаёт метрики с именами клиентов и их адресами.
  Требуется `PROMETHEUS_METRICS_PASSWORD` либо loopback-привязка.
- Порт 51821 — это же Web UI. Слабый пароль означает полный контроль над VPN.
- Контейнер работает от root (в образе не задан `USER`) и получает `NET_ADMIN` и
  `SYS_MODULE` — это даёт контейнеру возможность управлять сетевым стеком хоста.
  Образ из `ghcr.io`, не собирается локально.
- Правила `WG_POST_UP` по умолчанию закрывают клиентам LAN хоста. Сохраняйте их, если
  полный доступ в локальную сеть не требуется.
- Том `etc_amnezia_wg` содержит приватный ключ сервера и конфиги всех клиентов.
  Бэкапьте его отдельно и не храните в репозитории.
